# 猪猪存钱罐

猪猪存钱罐是一个面向个人投资组合的网页看板，用于统一查看 A 股、港股和美股的持仓、盈亏、市场机会与卖出记录。

- 线上地址：[https://alixjd.com](https://alixjd.com)
- 代码仓库：[dzhdingzihang/futuniuniu](https://github.com/dzhdingzihang/futuniuniu)
- 当前架构：Cloudflare Pages + Pages Functions

> 公开行情可能延迟或缺失。页面中的趋势、研究分和价格区间只用于研究排序与风险提示，不构成投资建议、买卖建议或收益承诺。

## 页面导航

网站保留四个主页面：

1. **总览**：账户整体、分市场概览、7/30/90 日累计盈亏估算曲线、个股盈亏排行。
2. **持仓明细**：当前持仓快照、市场结构、搜索与筛选、排序、个股两周技术展望。
3. **机会雷达**：扫描 A 股、港股和美股候选池，按透明规则生成研究优先级，并提供 10 个交易日价格参考。
4. **卖出记录**：查看已卖出批次，按市场和日期筛选，并按卖出时间、已实现盈亏、收益率升降序排列。

## 快速使用

1. 打开网站并输入 Cloudflare 环境中配置的密码。
2. 点击顶部“刷新”，更新持仓行情、历史日线和最新可用汇率。
3. 在“总览”确认账户和市场级盈亏。
4. 在“持仓明细”展开单只股票，查看当前仓位与未来 10 个交易日技术展望。
5. 在“机会雷达”筛选候选、查看评分依据和风险，再决定是否加入观察。
6. 使用“修改持仓”录入新持有或卖出批次；只有 GitHub 写入成功后，页面才确认保存。

## 总览

### 账户整体

所有账户级金额统一展示为人民币：

- **股票总投入**
  `Σ买入成本 − Σ卖出净额`。
- **持仓市值**
  `Σ有效估值价格 × 当前数量 × 最新可用汇率`。
- **累计盈亏**
  `持仓市值 − 股票总投入`。
- **累计收益率**
  `累计盈亏 ÷ 股票总投入`，仅在股票总投入大于 0 时计算。
- **今日盈亏**
  `Σ当日每股价格变化 × 当前数量 × 最新可用汇率`。
- **今日收益率**
  `今日盈亏 ÷（持仓市值 − 今日盈亏）`。

账户级市值和累计盈亏采用完整覆盖原则：只要有一只当前持仓缺少有效估值，组合合计就显示 `--`，不会把缺失证券当作 0。今日盈亏同理，必须所有当前持仓都有对应市场交易日的有效报价。

### 市场概览

港股、A 股、美股分别展示：

- 股票总投入
- 持仓市值
- 累计盈亏和累计收益率
- 今日盈亏和今日收益率
- 当前持仓数量
- 该市场占组合市值的比例

港股和美股同时展示市场原币与人民币口径。人民币累计盈亏包含汇率影响，因此不能简单用原币盈亏乘当前汇率反推。

### 累计盈亏走势

支持 7、30、90 天切换。曲线使用“当前持仓数量 × 历史收盘价 − 当前股票总投入”回看，因此它是**按当前仓位估算**的变化曲线，不是逐日恢复真实历史仓位的账户净值曲线，也不重演历史汇率。

### 个股盈亏排行

支持总体、港股、A 股、美股筛选，分别显示盈利与亏损个股。相同市场和股票代码的持有、卖出批次会按个股生命周期聚合；缺少有效估值的股票进入“待估值”，不会伪装为 0。

## 持仓明细

### 顶部快照

- 持仓数量
- 持仓市值
- 今日盈亏
- 当前持仓浮动盈亏
- 累计盈亏分布：盈利、亏损、持平、待估值
- 今日盈亏分布：上涨、下跌、持平、待行情

分布按“市场 + 行情代码”聚合后的股票数量计算，不按买入批次数重复计数。

### 仓位结构

结构条展示 A 股、港股和美股的市值占比，并补充最大单股仓位和前五大持仓集中度。缺估值的证券不参与虚假的比例计算，页面会同时显示估值覆盖情况。

### 搜索、筛选与排序

- 搜索股票名称或代码
- 按全部、A 股、港股、美股筛选
- 按全部、盈利、亏损筛选
- 按数量、当前价、市值/仓位、今日盈亏、累计盈亏排序
- 每个数值表头可切换升序或降序；缺失值始终排在末尾

### 个股字段

- **买入均价**：按数量加权的成交均价，不含手续费。
- **当前价/最近收盘**：优先使用有效报价；报价不可用时，可使用不超过 10 天的最近日线收盘做估值。
- **总成本**：买入本金加已分摊买入手续费。
- **市值/仓位**：有效估值价乘数量，再折算人民币；仓位为该股票市值占完整持仓市值比例。
- **今日盈亏**：同时展示市场原币和人民币；手续费不计入当日市场变化。
- **累计盈亏**：同时展示市场原币浮动盈亏和人民币会计口径；人民币口径包含汇率变化。

过期报价只作为行内参考，不进入组合完整估值；今日盈亏只有在报价属于相应市场当前交易日时才展示。

### 持仓两周技术展望

“两周”按未来 10 个交易日理解。模型必须满足：

- 至少 60 根有效日线；
- 最近 60 根 OHLC 覆盖率不低于 95%；
- 最近 20 根 OHLC 完整；
- 最后一根日线距当前不超过 5 天；
- 当前报价和对应市场基准数据可用。

方向判断使用 20 日波动、10/20 日标准化动量、SMA10、SMA20 及 5 个交易日前的 SMA20 斜率。A 股、港股、美股分别参考沪深 300、恒生指数、标普 500。

波动区间为：

```text
波动比例 = clamp(1.25 × 20日波动率 × √10, 4%, 30%)
参考区间 = 最新收盘价 × (1 ± 波动比例)
```

支撑和压力参考最近 20 日低点/高点，并结合 `0.25 × ATR14`。输出只有“上涨倾向”“下跌倾向”“无法分析”三态，不输出未经回测校准的上涨概率。

## 机会雷达

机会雷达是一套**趋势质量研究排序**，不是买入信号，也不是未来上涨概率。

### 候选池

每次扫描分别请求 A 股、港股、美股：

- 每个市场按成交额从高到低取 5 页，每页 100 条原始快照；
- 过滤、去重后少于 200 只时，该市场本期扫描失败关闭；
- 评分后每个市场保留前 240 只；
- 三个市场正常时最大候选池为 720 只。

基础资格过滤：

- 所有市场都要求价格、成交额和总市值有效；
- A 股排除部分北交所代码以及 ST、退市风险证券；
- 港股按名称排除基金、ETF、权证、牛熊证、杠杆和反向产品；
- 美股按名称排除 ETF、ETN、杠杆和反向产品；
- 当前持仓按行情代码或标准化名称从结果中排除。

当前版本没有完整的统一发行人、A/H/ADR、行业或底层资产映射，因此不能保证识别所有跨市场重复暴露。

### 研究优先级评分

所有分位数都在**同一市场内部**计算，研究分满分 100：

| 分项 | 权重 | 计算逻辑 |
| --- | ---: | --- |
| 趋势动量 | 35 | 60 日收益率分位 × 25 + 最近交易日涨跌分位 × 10 |
| 流动性与规模 | 30 | `log10(成交额)` 分位 × 20 + `log10(总市值)` 分位 × 10 |
| 短期稳定性 | 20 | `(1 − 振幅分位) × 12 + (1 − 绝对日涨跌分位) × 8` |
| 估值可比性 | 15 | `(1 − 正 PE 分位) × 9 + (1 − 正 PB 分位) × 6` |

缺失或非正的 PE/PB 在对应估值项计 0 分，不会伪造行业均值。

分档：

- `≥ 70`：优先研究
- `55–69.9`：候补观察
- `< 55`：暂不优先

分数用于决定“先研究谁”，不能跨市场解释为同等预期收益，也不能解释为胜率。

### 当前价、10 日参考上沿和风控止损参考

当前页只显示 10 只候选。系统仅为当前可见股票懒加载 90 根日线，每批最多 5 只，避免一次为 720 只拉取历史数据。

- 成功历史在当前页面会话缓存 30 分钟；
- 错误结果缓存 5 分钟，避免重复轰击上游；
- 最多保留 60 只股票的历史缓存；
- 雷达快照 6 小时内视为本期可用，失败时会明确标记缓存。

价位模型至少需要 61 根完整 OHLC，并拒绝以下异常：

- 未完成的盘中日线；
- 最后历史日期超过 10 天；
- 单日对数涨跌绝对值大于 `ln(1.5)`；
- 真实波幅占前收盘超过 35%；
- 雷达当前价偏离最近收盘超过 25%；
- 原始波动带超过 25%。

核心公式：

```text
σeff = max(σ20, 0.75 × σ60)
rawBand = max(1.25 × σeff × √10, ln(1 + 2 × ATR14 / 当前价))
band = max(rawBand, -ln(0.97))
10日参考上沿 = 当前价 × exp(band)
```

“10 日参考上沿”是历史波动情景上沿，**不是目标价或收益承诺**。

风控线由两个候选组成：

1. 波动止损：`当前价 × exp(-band)`
2. 结构止损：最近确认的 5 点收盘枢轴低点减去 `0.25 × ATR14`

只保留距离当前价至少 `max(3%, 1.5 × ATR14 / 当前价)` 且不超过 15% 的候选，取更接近当前价的一条。触发语义是“日收盘低于该价位后复核”，不是盘中碰到就自动交易。

### 展开详情与观察清单

详情解释：

- 总分与四项分数
- 入选依据与反方风险
- 60 日涨跌、振幅、换手率
- 成交额、总市值、PE、PB
- 当前市场在现有组合中的仓位占比
- 数据来源、扫描时间和模型版本

观察清单只保存在当前浏览器。保存时会剔除历史日线、参考上沿和止损价等易过期派生字段。

当前雷达没有使用财报、新闻、公告、事件日历、行业因子或机器学习预测；“估值可比性”也不等于公司基本面质量。

## 卖出记录

卖出记录来自 GitHub `holdings.json` 中带 `sell` 的批次。

支持：

- 按全部、A 股、港股、美股筛选；
- 选择卖出开始日期和结束日期，首尾日期都包含；
- 按卖出时间、已实现盈亏、收益率排序；
- 每种排序都可切换升序/降序；
- 一键清除日期和市场筛选。

字段口径：

- **买入成本**：对应卖出数量分摊的买入本金与买入手续费。
- **卖出金额**：卖出毛额减去卖出手续费后的净额。
- **已实现盈亏**：`卖出净额 − 买入成本`。
- **收益率**：`已实现盈亏 ÷ 买入成本`。
- **胜率**：当前筛选结果中，盈利卖出批次数占全部卖出批次数的比例。

## 修改持仓与 holdings.json

顶部“修改持仓”采用简化表单：

- 选择 A 股、港股或美股；
- 输入代码，自动识别名称、币种和行情代码；
- 选择“持有中”或“已卖出”；
- 输入买入价格和数量；
- 已卖出时再输入卖出价格、数量和日期；
- 新交易默认每次买入、每次卖出各计 `US$20` 手续费。

保存流程是 GitHub 确认优先：页面先调用 Cloudflare Function 写入 GitHub Contents API；GitHub 返回成功后才更新本地状态并关闭表单。失败时输入会保留，不能显示假成功。

### v2 示例

```json
{
  "version": 2,
  "newTradeFeeUsd": { "buy": 20, "sell": 20 },
  "lots": [
    {
      "market": "US",
      "code": "DEMO",
      "name": "示例公司",
      "buy": { "price": 100, "qty": 10 }
    },
    {
      "market": "HK",
      "code": "01234",
      "name": "示例港股",
      "buy": { "price": 50, "qty": 200 },
      "sell": { "price": 60, "qty": 80, "date": "2026-08-18" },
      "fees": { "buy": 20, "sell": 20 }
    }
  ]
}
```

- `market` 只填 `A`、`HK`、`US`。
- 没有 `sell` 表示持有；有 `sell` 表示该数量已卖出。
- `sell.qty` 不能大于 `buy.qty`；部分卖出会拆成卖出和剩余持有两部分。
- 文档未显式写 `fees` 时，使用顶层 `newTradeFeeUsd`；若某笔历史交易明确不计费，必须显式写 `fees: { "buy": 0, "sell": 0 }`。
- 修改同一证券会替换当前“持有中”记录，但保留既有已卖出记录。

## 统一会计与汇率口径

历史交易优先使用已经锁定的人民币字段：

```text
买入成本人民币 = purchaseCostCny
卖出净额人民币 = sellProceedsCny
```

旧记录没有锁定字段时使用参考汇率：

```text
买入成本人民币 = 买入价 × 数量 × 历史参考汇率 + 买入费USD × 7.22
卖出净额人民币 = 卖出价 × 数量 × 历史参考汇率 − 卖出费USD × 7.22
参考汇率：USD/CNY = 7.22，HKD/CNY = 0.92
```

历史成本使用记录或参考汇率固定，不会因今天汇率变化而重写。当前市值和今日盈亏使用 Frankfurter 返回的最新可用汇率；Frankfurter 不是逐笔实时外汇报价，页面会展示汇率日期、抓取时间、来源和是否使用固定回退值。

## 数据新鲜度与失败原则

- 有效报价优先用于当前估值。
- 报价不可用时，只允许不超过 10 天的最近历史收盘参与估值。
- 过期缓存只在行内标记参考，不进入组合完整估值。
- 今日盈亏必须有对应市场当前交易日的报价。
- 未来日期、异常 OHLC、部分批次缺价、NaN 和无穷值全部失败关闭。
- 数据不完整时显示 `--`、覆盖数量和原因，不把缺失当 0，也不把旧数据标成刚更新。

## 数据来源与 API

| 路由 | 用途 | 主要数据源 |
| --- | --- | --- |
| `GET /api/quotes` | 当前/延时报价 | 新浪为主，Yahoo 回退 |
| `GET /api/history` | 日线、基准、两周模型 | 美股 Yahoo 优先；其他东方财富优先；Yahoo、腾讯回退 |
| `GET /api/rates` | USD/CNY、HKD/CNY | Frankfurter，失败时固定参考值 |
| `GET /api/radar` | 三市场候选池与评分 | 东方财富行情中心 |
| `GET /api/security-lookup` | 代码识别名称 | 新浪，部分场景 Yahoo 回退 |
| `GET/POST /api/holdings-sync` | 读取/写入持仓 | GitHub Contents API |
| `POST /api/login` | 密码登录与会话 | Cloudflare Pages Function |
| `POST /api/logout` | 清除会话 | Cloudflare Pages Function |
| `GET /api/intraday` | 预留分时接口 | 当前前端未使用 |

历史接口支持 `idx_csi300`、`idx_hsi`、`idx_sp500` 三个基准别名。

## 登录、隐私与同步

- 密码只保存在 Cloudflare 加密 Secret 中，绝不能写入前端或 Git。
- 登录成功后使用 7 天有效的签名 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie。
- 顶部“退出”会调用 `POST /api/logout` 并清除会话。
- 页面、`holdings.json` 和 API 受登录中间件保护；`/assets/*` 与 `/pet/*` 静态资源不经过登录中间件。
- 启动时先使用本地缓存快速首屏，再用静态 `holdings.json` 兜底，并在后台以 GitHub 当前文件覆盖为权威数据；本地旧缓存不能反向覆盖成功读取的远端。

仓库当前是公开仓库，因此 GitHub 上的 `holdings.json` 和 `trades.json` 仍可被公开读取。网站密码不能隐藏公开仓库里的持仓、成本和数量；如需隐私，应先把仓库改为私有，并确认 Cloudflare Git 集成仍有权限。

## 已知限制

- 不是券商交易系统，不会自动下单。
- 两周方向和雷达价位是技术规则，不是概率模型或目标价。
- 累计盈亏曲线按当前仓位回溯估算，不能替代逐日资金流水净值。
- 缺少完整财务、新闻、公告、行业和统一发行人映射。
- 第三方公开行情可能延迟、限流、停牌或暂时不可用。
- 当天新买入持仓缺少精确买入时间时，今日盈亏仍按当前数量估算。
