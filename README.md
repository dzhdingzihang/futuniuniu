# 猪猪存钱罐

猪猪存钱罐是一个面向个人投资组合的网页看板，用于统一查看 A 股、港股和美股的持仓、盈亏、市场机会与卖出记录。

- 线上地址：[https://alixjd.com](https://alixjd.com)
- 代码仓库：[dzhdingzihang/futuniuniu](https://github.com/dzhdingzihang/futuniuniu)
- 当前架构：Cloudflare Pages + Pages Functions + 独立 Cron Worker + Cloudflare KV

> 公开行情可能延迟或缺失。页面中的趋势、研究分和价格区间只用于研究排序与风险提示，不构成投资建议、买卖建议或收益承诺。

## 页面导航

网站保留四个主页面：

1. **总览**：账户整体、分市场概览、7 / 30 / 90 / 365 / 1095 天累计盈亏估算曲线、个股盈亏排行。
2. **持仓明细**：当前持仓快照、市场结构、搜索与筛选、排序、个股两周技术展望。
3. **机会雷达**：创业板、港股科技和纳斯达克在交易日开盘前冻结最多三只大涨候选，收盘后验证。可切换盘中确认、成长板块和全市场研究榜。
4. **卖出记录**：查看已卖出批次，按市场和日期筛选，并按卖出时间、已实现盈亏、收益率升降序排列。

## 快速使用

1. 打开网站并输入 Cloudflare 环境中配置的密码。
2. 点击顶部“刷新”，更新持仓行情、历史日线和最新可用汇率。
3. 在“总览”确认账户和市场级盈亏。
4. 在“持仓明细”展开单只股票，查看当前仓位与未来 10 个交易日技术展望。
5. 在“机会雷达”筛选候选、查看评分依据和风险，再决定是否加入观察。
6. 使用顶部“记录交易”每次录入一笔买入或卖出流水；只有 GitHub 返回权威文档后，页面才确认保存。

## 总览

### 账户整体

所有账户级金额统一展示为人民币：

- **股票总投入**
  `Σ买入成本 − Σ卖出净额`。
- **持仓市值**
  `Σ有效估值价格 × 当前数量 × 最新可用汇率`。
- **累计盈亏**
  `持仓市值 − 股票总投入`。
- **累计收益率**
  `累计盈亏 ÷ 股票总投入`，仅在股票总投入大于 0 时计算。
- **今日盈亏**
  `Σ当日每股价格变化 × 当前数量 × 最新可用汇率`。
- **今日收益率**
  `今日盈亏 ÷（持仓市值 − 今日盈亏）`。

账户级市值和累计盈亏采用完整覆盖原则：只要有一只当前持仓缺少有效估值，组合合计就显示 `--`，不会把缺失证券当作 0。今日盈亏同理，必须所有当前持仓都有对应市场交易日的有效报价。

总览小字单独测算每张成交订单只收 2 美元时的全账户累计盈亏。它加回主指标中的每只股票的定额成本调整和可核实的订单手续费，再扣除假设费用。港美股历史买卖按账户和订单号去重，每单 2 美元按首个成交日的美元汇率折算；A 股历史订单和费用不全，沿用原表交易成本。网页新增的各市场买卖按操作编号计一次，按录入时锁定的汇率折算。当前估值不全时，小字显示有日期的 Excel 账本测算。

### 市场概览

港股、A 股、美股分别展示：

- 股票总投入
- 持仓市值
- 累计盈亏和累计收益率
- 今日盈亏和今日收益率
- 当前持仓数量
- 该市场占组合市值的比例

港股和美股同时展示市场原币与人民币口径。人民币累计盈亏包含汇率影响，因此不能简单用原币盈亏乘当前汇率反推。

### 累计盈亏走势

7、30、90 天沿用最近行情点数。365 天和 1095 天按北京时间的自然日选取，第一次选择时分批获取长期日线。横轴显示完整日期范围。有当前持仓尚未上市、某个市场缺价或历史数据不足时，仅绘制全部持仓都有可用价格的日期，并显示实际可估值区间。曲线用当前数量、当下汇率和当前净投入回算；历史持仓变化需另查交易记录。

### 个股盈亏排行

支持总体、港股、A 股、美股筛选，分别显示盈利与亏损个股。相同市场和股票代码的持有、卖出批次会按个股生命周期聚合；缺少有效估值的股票进入“待估值”，不会伪装为 0。

## 持仓明细

### 顶部快照

- 持仓数量
- 持仓市值
- 今日盈亏
- 当前持仓浮动盈亏
- 累计盈亏分布：盈利、亏损、持平、待估值
- 今日盈亏分布：上涨、下跌、持平、待行情

分布按“市场 + 行情代码”聚合后的股票数量计算，不按买入批次数重复计数。

### 仓位结构

结构条展示 A 股、港股和美股的市值占比，并补充最大单股仓位和前五大持仓集中度。缺估值的证券不参与虚假的比例计算，页面会同时显示估值覆盖情况。

### 搜索、筛选与排序

- 搜索股票名称或代码
- 按全部、A 股、港股、美股筛选
- 按全部、盈利、亏损筛选
- 按数量、当前价、市值/仓位、今日盈亏、累计盈亏排序
- 每个数值表头可切换升序或降序；缺失值始终排在末尾

### 个股字段

- **买入均价**：按数量加权的成交均价，不含手续费。
- **当前价/最近收盘**：优先使用有效报价；报价不可用时，可使用不超过 10 天的最近日线收盘做估值。
- **总成本**：买入本金加已分摊买入手续费。
- **市值/仓位**：有效估值价乘数量，再折算人民币；仓位为该股票市值占完整持仓市值比例。
- **今日盈亏**：同时展示市场原币和人民币；手续费不计入当日市场变化。
- **累计盈亏**：同时展示市场原币浮动盈亏和人民币会计口径；人民币口径包含汇率变化。

过期报价只作为行内参考，不进入组合完整估值；今日盈亏只有在报价属于相应市场当前交易日时才展示。

### 持仓两周技术展望

“两周”按未来 10 个交易日理解。模型必须满足：

- 至少 60 根有效日线；
- 最近 60 根 OHLC 覆盖率不低于 95%；
- 最近 20 根 OHLC 完整；
- 最后一根日线距当前不超过 5 天；
- 当前报价和对应市场基准数据可用。

方向判断使用 20 日波动、10/20 日标准化动量、SMA10、SMA20 及 5 个交易日前的 SMA20 斜率。A 股、港股、美股分别参考沪深 300、恒生指数、标普 500。

波动区间为：

```text
波动比例 = clamp(1.25 × 20日波动率 × √10, 4%, 30%)
参考区间 = 最新收盘价 × (1 ± 波动比例)
```

支撑和压力参考最近 20 日低点/高点，并结合 `0.25 × ATR14`。输出只有“上涨倾向”“下跌倾向”“无法分析”三态，不输出未经回测校准的上涨概率。

## 机会雷达

默认页是[盘前预测](https://alixjd.com/?radar=preopen#radar)。它每天回答一个有明确截止时间的问题：在各市场当地 09:25，当时有哪些股票具备证据，可能在当天交易时段最高涨到比昨收高 5%？

### 盘前预测与收盘验证

| 页面字段 | 计算口径 |
| --- | --- |
| 候选范围 | 创业板、恒生科技综合指数、纳斯达克上市普通股及存托凭证独立建榜。显示官方名册总数与实际证据覆盖，同一板块最多三只 |
| 数据截止与发布时间 | 交易日当地 09:15、09:20、09:24 采样。09:25 选用截止前最后完成的快照，开盘前发布。没有合格快照则本期缺数据。休市展示下次交易日 |
| 入选原因 | 检查上次收盘后已披露的正向公司事件、可核实的竞价或盘前成交、上一交易日的同业环境。至少两类成立才可入选，每条保留来源和时间。强势同行只计一类证据 |
| 盘前已跳涨 | 有可靠盘前成交且已较昨收上涨至少 5% 的股票单列。缺少可靠盘前价格时显示未核实 |
| 大涨门槛 | 冻结时逐股保存昨收，门槛为昨收 × 1.05。公司行动导致昨收口径对不上、日内行情不完整或报价过期时，记为缺数据 |
| 收盘验证 | 用当天正常交易时段的开、高、低、收验证。分别统计开盘已达到、盘中首次达到、收盘守住、冲高回落，另算开盘到收盘涨跌。五分钟线从开盘至首次触及完整时显示时间区间 |
| 三组比较 | 主榜、冻结时完整名册、昨日涨幅前三使用同样口径。命中率 = 盘中达到门槛的只数 ÷ 可核实只数。同时列出样本量、覆盖率和空榜天数，按市场累计最近 20 个已复核交易日 |

数据来自有范围限制的公开公告、行业分类和行情。美股对有限数量的候选逐只核对盘前成交。异常成交需要累积同一时点的历史样本。跨市场、跨来源的覆盖差异可在每期名单查看。无历史样本时仅展示规则和独立标注的虚构示例。完整规则见[当日大涨预测逻辑](docs/当日大涨预测逻辑.md)。

**盘中确认**在交易中每五分钟比较两次可核对的报价，显示触发时间、触发价、量价变化及收盘复核。**成长板块**按同类成长动量排序，**全市场**按趋势质量评分，两者的价格参考周期为十个交易日。

### 全市场研究榜

每次扫描分别请求 A 股、港股、美股：

- 每个市场按成交额从高到低取 5 页，每页 100 条原始快照；
- 过滤、去重后少于 200 只时，该市场本期扫描失败关闭；
- 评分后每个市场保留前 240 只；
- 全市场榜三个市场合计最多保留 720 只。另设独立的「成长板块」视图。

基础资格过滤：

- 所有市场都要求价格、成交额和总市值有效；
- A 股排除部分北交所代码以及 ST、退市风险证券；
- 港股按名称排除基金、ETF、权证、牛熊证、杠杆和反向产品；
- 美股按名称排除 ETF、ETN、杠杆和反向产品；
- 当前持仓按行情代码或标准化名称从结果中排除。

当前版本没有完整的统一发行人、A/H/ADR、行业或底层资产映射，因此不能保证识别所有跨市场重复暴露。

### 成长板块

切到「成长板块」可查看三份独立的 Top 3。每份榜单从官方证券名册按代码批量获取腾讯报价，再在同板块内评分。全市场成交额榜的 240 名截断不限制成长榜。两份榜单可能出现同一只股票，覆盖数量不能直接相加。

| 板块 | 官方名册及覆盖范围 | 评分前的流动性门槛 |
| --- | --- | --- |
| 创业板 | [深交所股票列表](https://www.szse.cn/market/product/stock/list/index.html)中板块为创业板的股票，含 302 开头的证券 | 成交额至少 2,000 万元人民币 |
| 港股科技 | [恒生科技综合指数 HSTCI](https://www.hsi.com.hk/en-hk/indexes/all-indexes/index-details/?seriesCode=hstcis)全体成份股，涵盖大型与中小型公司及多个科技相关行业 | 成交额至少 1,000 万港元 |
| 纳斯达克 | [Nasdaq Trader 上市目录](https://www.nasdaqtrader.com/dynamic/SymDir/nasdaqlisted.txt)中符合普通股、普通股存托凭证等条件的证券，过滤 ETF、优先股、权证、单位与测试券 | 成交额至少 500 万美元，股价至少 3 美元 |

名册任务在北京时间周一至周五 23:37 核对三家官方来源。全部成功且成份有变时更新 assets/radar-universe.json，保留各市场该版名册的核验日期 asOf。港股按官方每日成份报告提取，同时核对 HSTCI 公布的数量。每日行情扫描读取线上名册，手动刷新走同一套逻辑。

**覆盖数字。** total 为名单证券数，quotedCount 为同一报价交易日且价格、成交额、市值有效的股票数。最多接受 10 个自然日内的行情，按当地报价日期取覆盖最多的一日。该日有效股票不足名册 75% 时沿用旧板块并标记时间。scoredCount 为通过流动性门槛且评分字段齐全的数量，qualifiedCount 为达到全部入围门槛的数量。API 保留达标前 240 只，再按当前持仓过滤、依次取前三。条件不足可留空。

**成长动量分。** 在板块内取分位，近 10 个交易日实际涨幅占 40 分，近 60 个交易日涨幅占 20 分，最近交易日涨幅占 5 分，成交活跃度占 35 分。活跃度依次选量比、换手率、成交额占总市值，同板块统一使用覆盖至少三分之二样本的第一种指标。量比等于 1 表示与比较基准相当，后两项仅反映当日换手程度。缺少选定指标的个股不进入评分。

进入榜单需同时满足近 10 日上涨且处于板块第 60 百分位及以上、近 60 日上涨、最近交易日收涨、交易活跃度达到板块中位数、使用量比时量比至少为 1、综合得分至少 65。单日绝对涨跌达到 7%、日振幅达到 8% 或近 60 日上涨达到 60% 即排除。页面分别展示近 10 日实绩和未来 10 日参考上沿。尚未建立样本外的未来十日收益或跑赢基准的胜率。

### 每日更新与三地 Top 3

成长板块和全市场研究榜由独立 Cloudflare Cron Worker 在**每日北京时间 08:10**扫描，不依赖用户是否打开网站。Worker 把三个市场的统一快照写入 Cloudflare KV：

```text
KV 绑定：RADAR_SNAPSHOTS
KV 键：radar:latest:v1
快照协议：radar-snapshot-v2
Cron：10,40 0 * * *（北京时间 08:10 全量扫描、08:40 补扫）
```

- Pages 中的 `GET /api/radar` 只读取这份统一快照，快速返回三个市场的同一批次状态。
- 打开页面时先展示已发布的榜单，并单独补查过期、缺失或仍使用旧模型的市场。顶部“刷新”可并行重扫三个市场。页面补查保存在当前浏览器，后台定时任务更新共享快照。
- 定时扫描中某个市场失败时，该市场继承上一份有效结果并标记 `stale`；其他成功市场正常发布。
- 08:40 只补扫当天尚未成功的市场。全数失败时保留上次发布的行情和发布时间，另记本次尝试时间。首次扫描全部失败时，`publishedAt` 为空。上游单页瞬时失败先重试该页，五页仍不全则沿用完整旧榜。
- 快照中的 `publishedAt` / `attemptedAt` 描述发布与尝试时间；每个市场仍保留自己的 `fetchedAt` 和 `quoteUpdatedAt`。休市日或交易时段外，行情时间可能早于扫描时间。

每个市场的 Top 3 独立从完整候选池中选出，不受下方搜索、市场筛选、研究级别、分页或排序控件影响。排序顺序是：今日结果优先、研究分降序、成交额降序、总市值降序、代码稳定排序。当前持仓仍按行情代码或标准化名称排除。

Top 3 将股票名称、交易所报价时间、研究分、具体入选依据和主要风险放在同一张卡片上，可以直接加入观察清单。卡片并列显示当前价、10 个交易日的波动上沿和收盘风控线。跨市场列表按成交额排序时统一折算人民币。

### 研究优先级评分

所有分位数都在**同一市场内部**计算，研究分满分 100：

| 分项 | 权重 | 计算逻辑 |
| --- | ---: | --- |
| 趋势动量 | 35 | 60 日收益率分位 × 25 + 最近交易日涨跌分位 × 10 |
| 流动性与规模 | 30 | `log10(成交额)` 分位 × 20 + `log10(总市值)` 分位 × 10 |
| 短期稳定性 | 20 | `(1 − 振幅分位) × 12 + (1 − 绝对日涨跌分位) × 8` |
| 估值可比性 | 15 | `(1 − 正 PE 分位) × 9 + (1 − 正 PB 分位) × 6` |

缺失或非正的 PE/PB 在对应估值项计 0 分，不会伪造行业均值。

`radar-v1.2` 在基础分上再核对绝对风险。单日涨跌幅绝对值达到 7% 或日振幅达到 8%，短期稳定性最多扣 6 分，两项同时触发只扣一次。60 日涨幅达到 60%，趋势最多扣 8 分。触发上述任一门槛，或缺少日涨跌、有效振幅、60 日涨跌时，该股仍可在候选列表查看，但不进入 Top 3。符合条件的股票不足三只时，按实际数量展示。这些阈值用于筛选研究对象，尚无样本外收益验证。

分档：

- `≥ 70`：优先研究
- `55–69.9`：候补观察
- `< 55`：暂不优先

分数用于决定“先研究谁”，不能跨市场解释为同等预期收益，也不能解释为胜率。

### 当前价、10 日参考上沿和风控止损参考

当前页只显示 10 只候选。系统为当前可见股票与三地 Top 3 的并集懒加载 90 根日线，每批最多 5 只，避免一次为 720 只拉取历史数据。

- 成功历史在当前页面会话缓存 30 分钟；
- 错误结果缓存 5 分钟，避免重复轰击上游；
- 最多保留 60 只股票的历史缓存；
- 页面优先显示 KV 中最近一份可用快照；市场继承的旧结果会明确标记 `stale`，不会冒充刚刚扫描的数据。

价位模型至少需要 61 根完整 OHLC，并拒绝以下异常：

- 未完成的盘中日线；
- 最后历史日期超过 10 天；
- 无法核对报价日期，或报价已超过 10 天；
- 单日对数涨跌绝对值大于 `ln(1.5)`；
- 真实波幅占前收盘超过 35%；
- 雷达当前价偏离最近收盘超过 25%；
- 原始波动带超过 25%。

雷达请求 `/api/history?ohlc=1`，逐个数据源核对真实开高低收。每个来源有超时上限，近期日线缺失或过期时继续尝试其他来源。若最新完整收盘晚于评分快照，卡片标出较新的收盘日期，两周上沿、止损线和百分比统一按该收盘价计算。评分快照的日期单独保留。多个批次分别更新，切换筛选或翻页后仍可重新取得未完成的价位。

核心公式：

```text
σeff = max(σ20, 0.75 × σ60)
rawBand = max(1.25 × σeff × √10, ln(1 + 2 × ATR14 / 当前价))
band = max(rawBand, -ln(0.97))
10日参考上沿 = 当前价 × exp(band)
```

“10 日参考上沿”是历史波动情景上沿，**不是目标价或收益承诺**。

风控线由两个候选组成：

1. 波动止损：`当前价 × exp(-band)`
2. 结构止损：最近确认的 5 点收盘枢轴低点减去 `0.25 × ATR14`

只保留距离当前价至少 `max(3%, 1.5 × ATR14 / 当前价)` 且不超过 15% 的候选，取更接近当前价的一条。触发语义是“日收盘低于该价位后复核”，不是盘中碰到就自动交易。

### 展开详情与观察清单

详情解释：

- 总分与四项分数
- 入选依据与反方风险
- 60 日涨跌、振幅、换手率
- 成交额、总市值、PE、PB
- 当前市场在现有组合中的仓位占比
- 数据来源、扫描时间和模型版本

观察清单只保存在当前浏览器。保存时会剔除历史日线、参考上沿和止损价等易过期派生字段。

当前雷达没有使用财报、新闻、公告、事件日历、行业因子或机器学习预测；“估值可比性”也不等于公司基本面质量。

## 卖出记录

卖出记录来自 GitHub `holdings.json` 中带 `sell` 的批次。

支持：

- 按全部、A 股、港股、美股筛选；
- 选择卖出开始日期和结束日期，首尾日期都包含；
- 按卖出时间、已实现盈亏、收益率排序；
- 每种排序都可切换升序/降序；
- 一键清除日期和市场筛选。

字段口径：

- **买入成本**：对应卖出数量分摊的买入本金与买入手续费。
- **卖出金额**：卖出毛额减去卖出手续费后的净额。
- **已实现盈亏**：`卖出净额 − 买入成本`。
- **收益率**：`已实现盈亏 ÷ 买入成本`。
- **胜率**：当前筛选结果中，盈利卖出批次数占全部卖出批次数的比例。

## 记录交易与 holdings.json

顶部“记录交易”不再要求编辑整份 JSON，每次只录入一笔不可分割的交易流水：

- 选择“买入 / 加仓”或“卖出 / 减仓”；
- 选择 A 股、港股或美股，输入代码后自动识别名称、币种和行情代码；
- 填写成交日期、成交价格和数量；
- 买入会追加一个新 lot，不会覆盖同一证券之前的买入批次；
- 卖出只能选择已有持仓，服务器按 `buy.date` 从早到晚使用 FIFO（先进先出）跨 lot 扣减；
- 每次买入固定计 `US$20` 手续费，每次卖出也只计一次 `US$20`。一笔卖出跨多个 lot 时，卖出手续费按分配数量比例分摊，不会对每个拆分批次重复收取。

### 并发、重试与确认

浏览器向 `POST /api/holdings-sync` 发送一个系统生成的 `operationId`、当前 `expectedFileSha` 和单笔 `operation`。

- `operationId` 是幂等键。同一笔请求因网络重试多次到达，服务器只会应用一次。
- `expectedFileSha` 是打开表单时读到的 GitHub 文件版本。若其他页面已更新文件，服务器返回 `409 HOLDINGS_SHA_CONFLICT` 及最新权威文档，前端载入新版后请用户核对并重试，不会静默覆盖。
- 写入请求 15 秒超时时，结果被视为“不确定”而不是失败。前端立即 `GET /api/holdings-sync` 核对 GitHub 最新文档是否已包含同一 `operationId`；若暂时无法核对，保留表单和原 `operationId` 供安全重试。
- 只有 GitHub 返回完整的 `document`、`holdings` 与新 `fileSha` 后，页面才替换本地状态并显示成功。

### v2 格式与锁定字段

日常调整金额可以直接在总览点「调整成本规则」，填写人民币买入成本和卖出成本，预览影响后保存到 GitHub。每个市场内的同一代码，买入计一次，发生过卖出再计一次，包括部分卖出。加仓、再次卖出或清仓后重买均沿用同一只股票的规则。两项都可以填 0。

手动维护时只需改文件顶部的 `costPolicy.buyCny` 和 `costPolicy.sellCny`。流水中的锁定金额保留原始账面值，网站统一应用规则。新交易的每笔 US$20 手续费按交易单独计算。

日常手工新增一笔时只需要写最小字段；币种、持有状态、行情代码和默认手续费都由程序补全：

```json
{
  "market": "US",
  "code": "AAPL",
  "name": "苹果",
  "buy": {
    "date": "2026-11-08",
    "price": 220,
    "qty": 10
  }
}
```

卖出时不需要改原 lot，优先使用页面顶部的“记录交易”，服务器会按 FIFO 自动拆分。下面的锁定成本、汇率、幂等键和审计字段由系统生成，不是每次手工录入的必填项。

```json
{
  "version": 2,
  "costPolicy": { "buyCny": 2000, "sellCny": 1000 },
  "newTradeFeeUsd": { "buy": 20, "sell": 20 },
  "lots": [
    {
      "id": "lot-op_buy_demo",
      "market": "US",
      "code": "DEMO",
      "name": "示例公司",
      "buy": {
        "price": 100,
        "qty": 10,
        "date": "2026-08-01",
        "operationId": "op_buy_demo",
        "purchaseCostCny": 7364.4,
        "feeCny": 144.4,
        "fxAsOf": "2026-08-01",
        "fxSource": "Frankfurter"
      },
      "fees": { "buy": 20 }
    }
  ]
}
```

- `market` 只使用 `A`、`HK`、`US`；没有 `sell` 表示仍持有，有 `sell` 表示该拆分数量已卖出。
- `id` 是 lot 标识，`parentLotId` 在部分卖出时指回原 lot；`buy.operationId` 和 `sell.operationId` 用于追踪交易与幂等重试。
- `purchaseCostCny` 是含买入手续费的锁定买入成本；`sellProceedsCny` 是扣除卖出手续费后的锁定卖出净额。
- 网站将买入成本分配给该证券在文件中的第一个买入批次，同批次拆分按股数分摊。卖出成本从最早一次卖出的净额中扣除。旧文件已嵌入的 `buy.adjustmentCny` 在应用集中规则前会被扣回。
- `feeCny`、`fxAsOf`、`fxSource` 保留交易当时的手续费人民币金额、汇率日期和来源，防止历史成本被今天的汇率重写。
- 部分卖出会把原 lot 拆为剩余持有和已卖出两部分；锁定的买入成本、成本调整、买入手续费、卖出净额与卖出手续费都按数量分摊，最后一份吸收浮点尾差。
- 旧 v1 数组和旧 v2 文档仍可读；第一次通过新流程写入时会转为可读 v2 结构。
- 旧历史记录若确实不计费，必须显式保留 `fees: { "buy": 0, "sell": 0 }`；不要通过删除字段来表示免费。

### 从股票记录 Excel 更新

`holdings.json` 可以从统一股票记录表重新生成，不需要逐条复制 JSON。首次使用先安装导入器依赖：

```bash
python3 -m pip install -r scripts/requirements.txt
```

然后运行：

```bash
python3 scripts/import_holdings_from_excel.py \
  "/absolute/path/20261108股票记录.xlsx" \
  --output holdings.json --dry-run
```

去掉 `--dry-run` 即写入文件。已有文件默认沿用其成本规则。新文件默认买入 2000、卖出 1000，可用 `--buy-cost-cny`、`--sell-cost-cny` 分别覆盖。输出文件含网站新增交易或手工记录时，请先改用新输出路径对账；明确要用工作簿完整替换时使用 `--replace-trades`。

更新港美股流水时，工作簿保留「历史卖出基准」中的原始均价和股数。基准日以后的每笔卖单按交易日单独展示，同一订单当日多次成交合并为数量加权成交价。「实盘逐笔成交」按成交号与「人民币成本明细」核对，买入成本按工作簿的移动平均成本结转，卖出净额已扣实际费用。网站只保存批次标识，券商订单号、成交号与账户号留在本地工作簿。若后续拆合股或代码变更影响历史卖出单位，导入器会提示先核对。各市场最近估值日见 `source.valuationAsOfByMarket`。

导入器按工作簿核对持仓数量、卖出记录及人民币盈亏。2026-11-08 工作簿的核对结果如下：

- 股票总数为 80，只按规范化后的市场和代码去重；
- 当前持仓为 31 只，其中 A 股 12、港股 7、美股 12；
- 有过卖出的 63 只包括 49 只已清仓、14 只部分卖出。远东股份的 100 股卖出有成交记录；已实现成本结合券商累计盈亏反推，批次保留估算说明；
- 买入调整为 80 × ¥2,000，卖出调整为 63 × ¥1,000，合计 ¥223,000；
- 按 Excel 的估值日期与汇率，累计盈亏由 -¥261,399.85 调整为 -¥484,399.85；
- 缺少原始买卖明细的记录会标记 `quality: "trade-details-missing"` 并保留说明，不会在页面上把内部占位值当成真实成交价展示。

导入会覆盖目标 JSON，正式执行前应确保 Excel 确实是最新权威版本；页面后续通过“记录交易”写入仍使用同一套 v2 lot 和 GitHub 并发保护逻辑。

## 统一会计与汇率口径

历史交易优先使用已经锁定的人民币字段：

```text
买入成本人民币 = 原始 purchaseCostCny + 分配给该批次的买入成本调整
卖出净额人民币 = 原始 sellProceedsCny − 分配给该批次的卖出成本调整
```

旧记录没有锁定字段时使用参考汇率：

```text
买入成本人民币 = 买入价 × 数量 × 历史参考汇率 + 买入费USD × 7.22
卖出净额人民币 = 卖出价 × 数量 × 历史参考汇率 − 卖出费USD × 7.22
参考汇率：USD/CNY = 7.22，HKD/CNY = 0.92
```

新交易在提交时同时锁定交易币种兑人民币汇率、USD/CNY 手续费汇率、汇率日期和来源。历史成本使用记录或参考汇率固定，不会因今天汇率变化而重写。当前市值和今日盈亏使用 Frankfurter 返回的最新可用汇率；Frankfurter 不是逐笔实时外汇报价，页面会展示汇率日期、抓取时间、来源和是否使用固定回退值。

## 数据新鲜度与失败原则

- 有效报价优先用于当前估值。
- 报价不可用时，只允许不超过 10 天的最近历史收盘参与估值。
- 过期缓存只在行内标记参考，不进入组合完整估值。
- 今日盈亏必须有对应市场当前交易日的报价。
- 未来日期、异常 OHLC、部分批次缺价、NaN 和无穷值全部失败关闭。
- 数据不完整时显示 `--`、覆盖数量和原因，不把缺失当 0，也不把旧数据标成刚更新。

## 数据来源与 API

| 路由 | 用途 | 主要数据源 |
| --- | --- | --- |
| `GET /api/quotes` | 当前/延时报价 | 新浪为主，Yahoo 回退 |
| `GET /api/history` | 日线、基准、两周模型 | 美股 Yahoo 优先；其他东方财富优先；Yahoo、腾讯回退 |
| `GET /api/rates` | USD/CNY、HKD/CNY | Frankfurter，失败时固定参考值 |
| `GET /api/radar` | 读取 KV 中的三市场统一快照 | Cloudflare KV |
| `GET /api/radar?market=...` | 手动单市场实时扫描与评分 | 东方财富行情中心 |
| `GET /api/security-lookup` | 代码识别名称 | 新浪，部分场景 Yahoo 回退 |
| `GET/POST /api/holdings-sync` | 读取/写入持仓 | GitHub Contents API |
| `POST /api/login` | 密码登录与会话 | Cloudflare Pages Function |
| `POST /api/logout` | 清除会话 | Cloudflare Pages Function |
| `GET /api/intraday` | 预留分时接口 | 当前前端未使用 |

历史接口支持 `idx_csi300`、`idx_hsi`、`idx_sp500` 三个基准别名。

## 登录、隐私与同步

- 密码只保存在 Cloudflare 加密 Secret 中，绝不能写入前端或 Git。
- 登录成功后使用 7 天有效的签名 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie。
- 顶部“退出”会调用 `POST /api/logout` 并清除会话。
- 页面、`holdings.json` 和 API 受登录中间件保护；`/assets/*` 与 `/pet/*` 静态资源不经过登录中间件。
- 启动时先使用本地缓存快速首屏，再用静态 `holdings.json` 兜底，并在后台以 GitHub 当前文件覆盖为权威数据；本地旧缓存不能反向覆盖成功读取的远端。
- 记录交易弹窗会根据 GitHub 仓库元数据显示公开仓库隐私提醒，让用户在提交成本与数量前看到风险。

如果 GitHub 仓库是公开仓库，其中的 `holdings.json` 和 `trades.json` 就可被任何人绕过网站直接读取。网站密码不能隐藏公开仓库里的持仓、成本和数量；如需隐私，应先把仓库改为私有，并确认 Cloudflare Pages Git 集成和 `PIGGY_GITHUB_TOKEN` 仍有权限。

## 已知限制

- 不是券商交易系统，不会自动下单。
- 两周方向和雷达价位是技术规则，不是概率模型或目标价。
- 累计盈亏曲线按当前仓位回溯估算，不能替代逐日资金流水净值。
- 缺少完整财务、新闻、公告、行业和统一发行人映射。
- 第三方公开行情可能延迟、限流、停牌或暂时不可用。
- 当天新买入持仓缺少精确买入时间时，今日盈亏仍按当前数量估算。
